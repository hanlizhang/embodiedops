02 / ENGINEERING DEPTH

More than a training run.

The work spans learning, robot control and instrumentation. Each layer has a different failure mode and its own verification.

PYTORCH · LEROBOT · SMOLVLA

Adapt the action model.

Freeze the VLM and fine-tune the action expert and state projection with native masked Flow Matching. Keep the model's saved processors aligned with demonstration data and simulation inputs.

  • 461 training / 52 episode-disjoint validation episodes.
  • Episode-balanced, motion-mixture and reward-window sampling.
  • Fixed-noise validation, gradient audits and independent checkpoint reloads.

OPTIMIZATION & NUMERICS

Check what actually learns.

Audited finite gradients against changes in the forward weights. Built an FP32-master ablation to investigate small updates lost under native precision.

x(t) = t · noise + (1 − t) · action
target velocity = noise − action
loss = masked flow-matching error

The numerical change restored updates in 33 normalization tensors; held-out loss still worsened. Optimization mechanics and policy quality were checked separately.

ROBOCASA · MUJOCO · ROBOT CONTROLLERS

Make the interfaces agree.

Mapped left/right/wrist cameras, 16D state and normalized 12D action predictions into a mobile-manipulation controller. Converted and reordered commands across base, torso, end-effector and gripper interfaces.

  • 50 predicted actions per chunk; configurable execution horizon.
  • Base-frame OSC increments: translation and orientation mapping.
  • 10 Flow Matching integration steps at policy inference.

CLOSED-LOOP VALIDATION

Trace every control decision.

Recorded actual task success, per-door joint progress, end-effector trajectories and inference timing. Kept camera, processor, reset and checkpoint contracts consistent for paired comparisons.

Policy action → controller command
1 control step = 25 physics substeps
0.05 s control / 0.002 s physics

A renderer lifecycle fix resolved reproducible black-camera readback; invalid recordings were preserved and excluded.

CONTACT-LEVEL INSTRUMENTATION

Distinguish proximity from contact.

Logged geometry identities, active constraints and positive normal forces at every MuJoCo physics substep. Linked loaded contacts to end-effector trajectories and door motion.

  • 25 physics samples per control action.
  • Separate robot–door interaction from self-contact.
  • Privileged diagnostics stay outside the policy observations.

MEASURABLE FAILURE

Locate the loss of progress.

For the incomplete seed-43 rollout, loaded door contact ends after action 251 and closure settles around action 285. The policy reaches 600 actions with 13.11° remaining.

This supports a physical failure description that a video or offline loss alone cannot provide. A contact-force peak is not a net hand wrench or a hardware safety guarantee.

TOOL REGISTRY · EVIDENCE ROUTING

Turn diagnostics into an executable loop.

Implemented tools for observation-contract checks, instruction probes, trajectory/contact analysis, configuration changes, training and paired evaluation.

  • Branch on returned evidence and record the chosen action.
  • Version candidate configurations and model artifacts.
  • Bound subprocesses and preserve structured decisions and results.

INDEPENDENT VERIFICATION

Gate candidate promotion.

Evaluate matched scenes and require improved success without lost reference successes or unacceptable door/contact regressions. Final scenes remain reserved until a candidate qualifies.

The executed decision backend is deterministic. The model-driven extension is being developed with NVIDIA Nemotron; this demo presents the verified tool and robot-learning foundation.

Earlier adaptation pilot

A separate 300-update natural-language experiment completed 3/10 tasks versus 0/10 pretrained across paired scenes. It uses a different protocol and is kept separate from this comparison.

Local resource footprint

Native sustained training peaked at 1.73 GiB allocated CUDA memory. The terminal run took 109 minutes; the FP32 run took 133 minutes and peaked at 2.65 GiB. Energy was not measured.

Technical case study · Why lower offline loss did not improve manipulation

Reward-aligned terminal sampling emphasized full action chunks around first success in demonstrations. It improved the targeted offline objective, while degrading approach/contact behavior in closed-loop execution.

04 / TOWARD AGENTIC POLICY ENGINEERING

Tools that can act
on a diagnosis.

The robot-learning backend and evidence tools form an executable foundation for model-driven experiment selection.

01 / OBSERVE

Collect evidence

Rollout outcomes, action/state contracts, trajectories and physical contacts.

02 / DIAGNOSE

Run a probe

Check instructions, cameras and execution; choose the next tool from returned evidence.

03 / REPAIR

Build a candidate

Apply a configuration change or run targeted imitation learning with versioned artifacts.

04 / VERIFY

Test and decide

Evaluate paired scenes and accept or reject against independent regression criteria.

IN DEVELOPMENT

NVIDIA Nemotron

Connecting a reasoning model to the existing diagnostic tools for hypothesis updates and probe selection. An endpoint adapter exists; live model-driven decisions are not yet part of the verified demo. Completed workflow executions use evidence-based rules.

Scope: simulated manipulation, pretrained VLA fine-tuning and controlled policy diagnosis. Historical experiment hypotheses were human-directed. The project has not yet established robust policy improvement or autonomous learning-based repair.
